---
title: "Compressed URLs"
description: "Production-ready compact URLs for ogis image generation"
---

Compressed URLs are the recommended way to embed ogis image generation in production. They encode all image parameters into a compact, base64url-safe blob and fit easily inside HTML `<meta>` tags, CDN rules, and caching keys - without long query strings.

<Info>
  The query-parameter API (`GET /`) is best for exploration and debugging. Use compressed URLs when building applications or integrating SDKs.
</Info>

## URL Shapes

### Unsigned

```
GET /c/{blob}
```

Use when your ogis instance has no HMAC authentication configured.

### Signed

```
GET /c/{blob}/{sig}
```

Use when `OGIS_HMAC_SECRET` is set on the server. The `sig` segment is the first 8 hex characters of the HMAC-SHA256 signature computed over the blob by the SDK.

## Path Parameters

| Parameter | Description |
|-----------|-------------|
| `blob` | Base64url-encoded compressed parameter blob, produced by an ogis SDK |
| `sig` | *(Signed form only)* 8-character HMAC-SHA256 prefix authorising the blob |

## Response

Returns a PNG image with dimensions 1200×630 pixels.

- **Content-Type**: `image/png`
- **Status**: `200 OK`

## Producing Blobs

Blobs are generated by ogis SDKs, not constructed by hand. The SDK encodes your parameters, compresses them, prepends a version byte, and base64url-encodes the result.

```typescript
// Illustrative - official SDKs pending; 'ogis' is a placeholder package name
import { OgisClient } from 'ogis';

const ogis = new OgisClient({ baseUrl: 'https://img.ogis.dev' });

// Returns a /c/{blob} URL ready to use in <meta> tags
const url = ogis.compressedUrl({
  title: 'Hello World',
  description: 'My first Open Graph image',
  template: 'twilight'
});
```

## Version Stability

Every blob begins with a version byte that encodes the wire format. This means:

- URLs generated today will remain decodable by future versions of the server.
- The server can handle multiple wire formats simultaneously.
- When a new format is introduced, old URLs keep working - they are never invalidated.

## Error Responses

| Status | Reason |
|--------|--------|
| `400 Bad Request` | Malformed blob or unrecognised format version |
| `401 Unauthorized` | Authentication required - missing or invalid signature |
| `403 Forbidden` | SSRF blocked (request to private IP) |
| `404 Not Found` | Unknown template name (falls back to default if deleted) |
| `422 Unprocessable` | Invalid image URL inside the blob, unsupported format, or image too large |
| `500 Internal Server Error` | Rendering failed |
| `502 Bad Gateway` | Upstream image fetch failed |
| `503 Service Unavailable` | Server overloaded, try again later |
| `504 Gateway Timeout` | Image fetch timed out |
